Inference stacks done properly.

One model layer for every AI application on your machine.

Chat for twenty minutes, walk away, and the same GPU goes back to indexing your documents and photos. Marigold is a self-hosted inference platform: applications share one model cache and one queue instead of each bringing its own model server. Chat and embeddings on OpenAI-compatible endpoints, image, speech and the other model types on a typed API -- on a laptop, a box at home, or your own cloud account, air-gapped once models are cached.

Applications, not just endpoints

01

Models are the stable layer

One shared weight cache, independent of which application is running. Downloaded once, reused by everything that needs it.

02

Applications are the thin layer

A marigold.toml, a models.yaml and the code that uses them, installed from a registry by name. The code runs in its own container and reaches models only through the API, never on the host.

03

Why this split matters

We've written about this at length: models as a fat protocol, applications as thin clients on top -- the same shape that made early internet protocols durable. Read the essay →

From a laptop to your own cloud account

01

A laptop or a box at home

Everything under one directory: the bundled Postgres, a local GPU or CPU worker, outputs on disk. Several applications share it, and requests queue rather than fight for the GPU.

02

A startup

A managed Postgres such as Supabase, rented GPU instances as workers, outputs in an S3 bucket. The same applications, with more throughput: add a GPU host and nothing else changes.

03

An institution

AWS RDS or Azure Database for PostgreSQL, GPU instances and object storage, all in your own account. Nothing routed through a third party. Deployment →

What runs on it

Content ingestion and moderation

Extract text, embed, classify, and gate restricted content before it reaches an index. Text and image embeddings in one pipeline enable cross-modal search.

img2txt text-embedding instruct image-embedding

Quality-gated image generation

Generate, score for safety, aesthetic quality, and prompt alignment. Regenerate automatically until thresholds are met or attempts run out.

txt2img image-eval image-text-eval

Visual conformance checking

Compare an observation image against a reference by structural embedding. On deviation, segment both, diff the masks, and describe the discrepancy in natural language.

image-embedding img2mask img2txt instruct

Document briefing and audio delivery

Extract entities, classify, summarise, and convert to speech in multiple languages from one application run. Output: a summary plus audio per language.

img2txt instruct tts

Batch tabular classification

Classify large volumes of unlabelled rows against a small labelled set. Low-confidence predictions go to an instruct model for explanation. No retraining.

text-embedding instruct

Site monitoring with change detection

Embed and compare images from multiple locations in parallel. On change, describe it and assemble a report, delivered as text and audio on a schedule.

image-embedding img2txt instruct tts

Each of these is a set of small applications. The ones that recur are the basis of a standard library for Marigold applications.

What the platform does

Models

  • Instruct, with OpenAI-compatible chat and tools
  • Text and image embeddings
  • Vision: img2txt, img2mask, depth
  • Speech and audio: tts, asr, txt2audio
  • Image and video generation
  • Text, image and image-text evals

Every model type →

Applications

  • Installed by name from any registry
  • Dependencies on other applications, installed with them
  • One model cache and one worker shared by all of them
  • Deterministic archives, checked by sha256 on install
  • A registry is static files: GitHub Pages or any host
  • Each instance in its own container, API access only
